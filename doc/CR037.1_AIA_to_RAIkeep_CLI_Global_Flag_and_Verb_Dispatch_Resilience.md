## 1. Problem Statement & Incident Description

During live operational testing of `PitSeeder` (`pits`) against OneDrive storage, a severe usability and parsing defect was identified when modifier flags (`-n` / `--nologo`) preceded a subcommand verb (`export`):

### Reproductions & Observed Behaviors

1. **Standard Subcommand (Succeeds):**
   ```bash
   pits export -c OneDrive -r AIA Person --json
   ```
   *Result:* Exits `0`. Correctly parses verb `export`, targets `Person.pit`, and emits JSON.

2. **Shorthand Root Form (Succeeds):**
   ```bash
   pits -n Person -c OneDrive -r AIA --json
   ```
   *Result:* Exits `0`. Correctly identifies shorthand viewer invocation on `Person.pit` with logo suppressed.

3. **Leading Flag with Explicit Verb (Fails Cryptically):**
   ```bash
   pits -n export Person -c OneDrive -r AIA --json
   ```
   *Result:* **Exits non-zero with fatal I/O error:**
   ```text
   '/Users/RSB/Library/CloudStorage/OneDrive/OneDriveData/AIA/export/export.pit' does not exist.
   ```

4. **Flag, Verb, Addressing, and Positional Item (Fails Cryptically):**
   ```bash
   pits -n export -c OneDrive -r AIA Person --json
   ```
   *Result:* **Exits non-zero with fatal I/O error:**
   ```text
   Pit file '/Users/RSB/Library/CloudStorage/OneDrive/OneDriveData/AIA/export/export.pit' does not exist.
   ```

## 2. Root Cause Analysis

The root cause stems from the collision between **canonical subcommand grammar** and the CLI's **shorthand entity viewer**:
1. When `pits <PitName>` is invoked without a verb, the CLI defaults to viewing/exporting the pit.
2. When an option like `-n` appears at `args[0]`, the root parser fails to find a registered verb at the first index, assumes the user is invoking the shorthand root syntax, and treats the next token (`"export"`) as the positional `<PitName>`.
3. The CLI then attempts to load `<root>/export/export.pit`.
4. Downstream I/O fails because no such pit exists, masking a simple command-line syntax error as a missing database file.

### Cross-Tool Suite Vulnerability
This defect is not isolated to `pits`. Because `PitSeeder` (`pits`), `ImgSeeder` (`iorg`), and `RaidSeeder` (`raid`) share command dispatch patterns and `OsLibCore` command-line utilities, this trap threatens the entire v4.4.1 suite:
- `raid -n export ...` or `raid -n refresh ...`
- `iorg -n list ...` or `iorg -n move ...`

## 3. Product Semantics & Architectural Invariants

### 3.1 Informative Standalone Flags (`-v`, `-h`)
Standalone informative flags take unconditional precedence and execute immediately:
- If `-v` / `--version` is passed anywhere in the arguments (`pits -v`, `pits export -v`, `pits -v export`), the CLI prints the version string and exits `0` immediately without executing further commands or checking filesystem paths.
- If `-h` / `--help` is passed without a verb, it prints root help and exits `0`. If passed with a verb (`pits export -h`), it prints verb-specific help and exits `0`.

### 3.2 Canonical Verb-First Grammar
When an explicit subcommand verb is used, **it must be the first argument** (`args[0]`):
```bash
pits <verb> [options] [arguments]
raid <verb> [options] [arguments]
iorg <verb> [options] [arguments]
```
Modifier flags (`-n`, `-d`, `-c`, `-r`, `-t`) cannot precede the verb.

### 3.3 Reserved Verb Protection
Registered verbs are reserved system keywords across the tool suite:
- **`PitSeeder` (`pits`):** `export`, `import`, `maintain`, `validate`
- **`ImgSeeder` (`iorg`):** `list`, `move`, `clean`, `validate`
- **`RaidSeeder` (`raid`):** `import`, `export`, `refresh`, `validate`

A positional entity argument (`PitName`, `ItemId`, `DiagramId`) can **never** silently bind to a reserved verb string.

### 3.4 Actionable Syntax Diagnostics (Fail Fast with Guidance)
If a reserved verb is detected anywhere in `args[1..]` (e.g. preceded by `-n` or addressing options):
1. The parser must immediately abort before executing any filesystem or database operations.
2. Exit with code `2` (CLI syntax error).
3. Emit a clear, human-readable error stating that the verb must be the first parameter, followed by the exact corrected command line.

**Example Diagnostic Output:**
```text
Error: Subcommand 'export' must be the first parameter.
Try:   pits export -n -c OneDrive -r AIA Person --json
```

## 4. Required Suite Unit Tests (`Burkhardt/RAIkeep`)

Codex (`702x`) must implement automated regression tests in `OsLibCore.Test`, `PitSeeder.Test`, `ImgSeeder.Test`, and `RaidSeeder.Test` verifying:

```csharp
[Fact]
public void MisplacedVerb_FailsFastWithActionableCorrection()
{
    var result = RunPits("-n export -c OneDrive -r AIA Person --json");

    Assert.Equal(2, result.ExitCode);
    Assert.Contains("Subcommand 'export' must be the first parameter", result.StdErr);
    Assert.Contains("pits export -n -c OneDrive -r AIA Person --json", result.StdErr);
}

[Theory]
[InlineData("pits -v export", "pits v4.4.1")]
[InlineData("pits export -v", "pits v4.4.1")]
public void VersionFlag_TakesImmediatePrecedence(string commandLine, string expectedVersion)
{
    var result = RunPits(commandLine);
    Assert.Equal(0, result.ExitCode);
    Assert.Contains(expectedVersion, result.StdOut);
}
```

Equivalent tests must be verified for `raid` and `iorg`:
- `raid -n refresh SignContract ...` $\rightarrow$ Error suggesting `raid refresh -n SignContract ...`
- `iorg -n list -t AfricaStage ...` $\rightarrow$ Error suggesting `iorg list -n -t AfricaStage ...`
